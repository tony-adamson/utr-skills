# utr-skills

Два скилла для Claude Code и Codex. Агент отвечает на **упрощённом техническом русском (УТР)**:
коротко, однозначно, без канцелярита. Структура — ASCII-схемой прямо в ответе, сложная
тема — HTML-страницей по просьбе.

| Скилл | Что делает | Вызов |
|---|---|---|
| `utr` | Ответы по правилам УТР из ГОСТ Р 58049-2017 | `/utr` · `$utr` |
| `utr-poh` | Синтаксис УТР + статусы по шкале мата из [pohuy](https://github.com/smixs/pohuy). 18+ | `/utr-poh` · `$utr-poh` |

## Откуда идея

Андрей Карпаты [предложил](https://x.com/karpathy/status/2105819303471976479) менять формат
ответа модели под задачу:

- текст — в контролируемом языке ASD-STE100 («примерно на 80%»);
- структура — диаграммой;
- сложная тема — интерактивной HTML-страницей.

ASD-STE100 — английский стандарт. У русского есть свой аналог:
**ГОСТ Р 58049-2017**, раздел 8.2 «Общие требования к упрощённому техническому русскому
языку». Стандарт написан для перевода документации авиатехники и прямо ссылается на STE100
как на образец. Скилл `utr` переносит эти правила в чат с агентом.

## До и после

Вопрос: «Почему компонент React ре-рендерится?»

**Обычный ответ:**

> Ре-рендеринг компонента осуществляется вследствие того, что при каждом рендере родителя
> происходит создание нового объекта, передаваемого в пропсы, что приводит к изменению ссылки.

**`/utr`:**

> Родитель создаёт inline-объект на каждый рендер. Ссылка на объект меняется. React видит
> новый проп и перерисовывает компонент. Оберни объект в `useMemo`.

**`/utr-poh`:**

> Хуйня вопрос. Родитель создаёт inline-объект на каждый рендер. Ссылка меняется,
> и React перерисовывает компонент. Оберни объект в `useMemo`.

## Правила УТР

Из ГОСТ Р 58049-2017, п. 8.2:

- предложение — до 20 слов, одна мысль;
- прямой порядок слов, действительный залог;
- глагол вместо отглагольного существительного, не больше двух существительных подряд;
- меньше причастных и деепричастных оборотов;
- одно понятие — один термин, без синонимов;
- инструкция: глагол первым, одна команда на предложение;
- предупреждение — до действия, а не после;
- абзац — одна тема, до 6 предложений.

Три отступления для чата:

1. Обращение на «ты»: «запусти», а не «запускайте». ГОСТ требует множественное число.
2. Устоявшиеся IT-термины («деплой», «коммит», «ребейз») остаются. ГОСТ требует русские
   эквиваленты.
3. Код, команды и строки ошибок — байт в байт.

Правила держатся примерно на 80%: нарушение допустимо, если иначе теряется смысл.

## Формат ответа

| Содержание | Форма |
|---|---|
| Факт, ответ, инструкция | Текст |
| Связи, поток, состояния | Текст + ASCII-схема (агент добавляет сам) |
| Сложная тема | HTML-страница — только по просьбе: `/utr html` |

Для HTML скилл использует [archify](https://github.com/tt-a1i/archify), если он
установлен. Иначе агент пишет один самодостаточный `.html` и открывает его в браузере.

## utr-poh

Шкала состояний из pohuy — это контролируемый словарь: одна ступень — одно слово.
УТР требует того же от терминов. Поэтому `utr-poh` берёт из pohuy шкалу из 10 ступеней
(от «охуенно» до «полный пиздец») и короткий словарь статусов, оценок и действий, а синтаксис — из УТР.

Чего в `utr-poh` нет, в отличие от pohuy: присказок, образных сравнений, хуенитивов
и уровня ultra. УТР запрещает метафоры и сравнения (п. 8.2.3.5).

Границы из pohuy сохранены:

- мат только о багах, коде и процессах, никогда о людях;
- код, коммиты, PR и документация — без мата;
- предупреждения о безопасности и необратимых операциях — без мата.

## Установка

```bash
git clone https://github.com/tony-adamson/utr-skills
cd utr-skills
./install.sh --all      # или --claude, --codex
```

Скиллы ставятся в `~/.claude/skills` и `~/.codex/skills`. `utr-poh` читает правила
из соседнего `utr`, поэтому installer всегда ставит оба. Повторная установка
перезаписывает каталоги `utr` и `utr-poh` целиком: свои правки вноси в репо,
а не в копию. После установки перезапусти
сессию агента.

Оба скилла включаются только явной командой и держатся до конца сессии.
Выключение — «нормальный режим», `/utr off` или `/utr-poh off`.
